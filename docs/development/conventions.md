# Engineering Conventions

- Prefer simplicity; avoid over-engineering and abstractions without a practical need.
- Keep changes scoped to the requested task.
- Do not add unnecessary dependencies or infrastructure.
- Inspect existing code and configuration before changing them.
- Keep backend and firmware as separate modules.
- Do not create nested Git repositories.
- Verify changes with the affected module's available build or test command.
- Use clear names and existing project conventions.
- Demo/calibration thresholds must not be represented as universal physical safety or cargo-damage limits.
